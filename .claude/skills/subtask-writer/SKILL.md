# subtask-writer

## Purpose

Write subtasks based on a product backlog.

Define context of subtasks based on a product backlog dividing a history into subtasks.

Use divide and conquer approach.

## Inputs

- Product Backlog History.
- Acceptance Criteria.
- Existing project.

## Deliverables

- Subtasks.
- Considerations.
- Tests scenarios.

## Output style

- Be concrete and structured.
- Consider exceptions.
- Use priority or severity when useful.
- Use divide and conquer approach.
- Use Portuguese-BR.
- Generate markdown files.
- Commented code must have technical content, not references of architecture, design doc's and product backlog.

## Failure modes to avoid

- Do not create too extensive subtasks.
- Do not recommend a style because it sounds modern.
- Do not hide uncertainty behind definitive language.
- Do not ignore existing project.
- Do not create comments referencing backlogs, design docs or defined documents in architecture project.

## Output

- Subtasks written in markdown files.
- Exceptions considerations.
- Test scenarios.
- Use templates/subtask-template.md
